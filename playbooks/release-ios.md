## Goal

A signed build with the intended backend URL is running on the target iPhone
(Path A) or is processing in TestFlight (Path B).

## Preconditions

- `ios` CI green on `main`: `gh run list --workflow ios.yml --branch main --limit 1`.
- `brew list xcodegen` succeeds; `xcodebuild -version` shows Xcode 16.4 or newer.
- `ios/Config/Local.xcconfig` exists with `SNAPSELL_BACKEND_URL` (copy `Local.xcconfig.example`).
- For Google sign-in builds: `ios/SnapSell/Resources/GoogleService-Info.plist` present and `GOOGLE_REVERSED_CLIENT_ID` set in `Local.xcconfig`. Without them the build only offers the dev bypass.

## Steps

### Common

1. `cd ios && xcodegen generate`.
2. Unit tests: `xcodebuild test -project SnapSell.xcodeproj -scheme SnapSell -destination 'platform=iOS Simulator,id=48668AB7-04A7-4385-955E-72C5F3CA69A2' CODE_SIGNING_ALLOWED=NO 2>&1 | tail -5` must end in `** TEST SUCCEEDED **`.
3. Pick a build number: `date -u +%Y%m%d%H%M` (must be higher than the last one uploaded to TestFlight; direct-to-device does not care).

### Path A: direct to device (current default)

4. `[HUMAN]` plug the iPhone in, unlock it, trust the Mac if prompted. Then: `xcrun xctrace list devices | grep -i iphone` and note the device UDID.
5. Build and install:
   ```bash
   xcodebuild -project SnapSell.xcodeproj -scheme SnapSell -configuration Release \
     -destination "id=<DEVICE_UDID>" -allowProvisioningUpdates \
     CURRENT_PROJECT_VERSION=<BUILD> -derivedDataPath build/device build
   xcrun devicectl device install app --device <DEVICE_UDID> build/device/Build/Products/Release-iphoneos/SnapSell.app
   xcrun devicectl device process launch --device <DEVICE_UDID> com.victorivanov.snapsell
   ```
   First install on a new phone: `[HUMAN]` Settings -> General -> VPN & Device Management -> trust the developer profile.

### Path B: TestFlight (once configured)

4. `[HUMAN]` one-time: App Store Connect -> Apps -> + -> iOS, name `SnapSell`, bundle id `com.victorivanov.snapsell`, SKU `snapsell`.
5. `[HUMAN]` one-time for CI: repo secrets `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (`base64 < ~/.private_keys/AuthKey_48M5JQ79S5.p8`), optional `GOOGLE_SERVICE_INFO_PLIST_B64`; variables `SNAPSELL_BACKEND_URL`, `GOOGLE_REVERSED_CLIENT_ID`.
6. Either tag: `git tag ios-v<marketing>.<build> && git push origin ios-v<marketing>.<build>`, or from this Mac: `[HUMAN]` supplies `ASC_ISSUER_ID`, then `ASC_KEY_ID=48M5JQ79S5 ASC_ISSUER_ID=<uuid> ios/scripts/testflight.sh <BUILD>`.
7. Processing takes 10-30 min; then App Store Connect -> TestFlight -> Internal Testing -> add testers.

## Verification

- Path A: the app icon is on the phone; Settings screen shows the expected backend URL; the inventory screen loads.
- Path B: `gh run watch` ends green, and the build appears under TestFlight with the chosen build number.
- Either: from the phone, identify one item; the VPS log shows the request: `docker compose -f /opt/snapsell/deploy/docker-compose.yml logs --since 5m backend | grep identify`.

## Rollback

- Path A: reinstall the previous build (`build/device` from the previous run, or rebuild at the previous SHA with the same commands).
- Path B: App Store Connect -> TestFlight -> expire the bad build; testers keep the previous one.
